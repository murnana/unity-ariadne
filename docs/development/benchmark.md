# 効果測定(2026-07-07)

グラフの有無で、AI エージェント(Claude Code)による同一調査タスクのトークン消費がどう変わるかを測定しました。成功基準は「30%以上削減」としました。

## 方法

- 実行系: `claude -p --output-format json`(Claude Code 2.1.201、モデル `claude-sonnet-5`、max-turns 40)を使用しました。対話セッションの `/usage` の代わりに、結果JSONの `usage`(input + output + cache read + cache creation の合計)と `total_cost_usd` を採用しています
- 対象: テストフィクスチャの URP プロジェクト(シーン3・プレハブ141・スクリプト17)のクローンです(Assets / ProjectSettings / Packages のみ。CLAUDE.md も git もない素のディレクトリ — 開発リポジトリのドキュメントに答えに繋がる事実が書かれているため、コンテキスト汚染を排除しました)
- ツール制限: 両条件とも読み取り専用(Read / Glob / Grep + rg / grep / find / sqlite3 等の読み取り系Bashのみ許可)としました
- グラフあり条件: プロンプトに graph.db(PackageCache込みで `analyze` した78,234 refs)のパスとスキーマ要約を付与し、sqlite3での照会を許可しました。グラフなし条件は同一タスク文のみです
- 正解は事前にグラフDBから抽出して確認しました(各セル n=1)

## 考察

- **逆依存(「誰がこれを参照しているか」)を問うタスクでグラフが圧倒的に効きます。** アセット参照はGUID文字列のため、グラフなしでは「.metaからGUIDを引く→プロジェクト全体をgrep」の往復が必要になります。特にタスク2(141プレハブ×全ファイル種の突合)はグラフなしで50ターン・304万トークン・15分かかりましたが、グラフありなら refs テーブルへのクエリ数回で終わります(88%削減)
- **コードシンボルの検索(タスク3)はgrepで既に最適**で、グラフの恩恵はありません(スキーマ説明分むしろ僅かに増えます)。グラフの価値はコード側ではなく、grepが効かないアセット層・GUID層にあります
- 正答性は全条件で同一でした(全問正解)。削減されたのは正しさではなく探索の往復です
- 成功基準「30%以上削減」は3タスク合計84%で**達成**しました。ただしタスク性質への依存が大きい点にご留意ください(上記のとおり逆依存系で効き、シンボル検索系では効きません)

## 制約

- 各セル1回のみの測定です(n=1)。LLMの探索経路は非決定的なため数値は目安としてご覧ください
- グラフあり条件は「プロンプトにスキーマとDBパスを渡してsqlite3を許可」した形です。MCPサーバー経由ではツール定義の常駐コスト等が変わりうる点にご注意ください
- コストの大半はキャッシュ読み取りのため、コスト差(4.1倍)はトークン差(6.3倍)より小さく出ています
